# 京东订单池设计

## 目标

从 `data/raw_order_responses.jsonl` 中提取所有订单，以 `orderId` 为唯一键建立本地订单池。订单池保存每笔订单最新一次出现时的完整京东原始订单对象，同时保存该订单第一次进入原始采集日志的具体时间。

## 文件格式

默认输出文件为 `data/order_pool.json`：

```json
{
  "订单号": {
    "first_seen_at": "2026-07-29T15:34:54.890657+08:00",
    "order": {
      "orderId": "订单号",
      "京东返回的其他字段": "保持原样"
    }
  }
}
```

订单号统一转为字符串作为 JSON 对象的键。`order` 不增加、删除或转换京东返回的任何字段。

## 构建规则

程序按原始 JSONL 的行顺序和每个响应中 `resultList` 的顺序处理订单：

1. `orderId` 第一次出现时，创建订单池条目；`first_seen_at` 取该原始日志行的 `captured_at`。
2. 相同 `orderId` 后续再次出现时，用后出现的完整订单对象覆盖 `order`。
3. 覆盖订单时不修改 `first_seen_at`。
4. 全量重建时，结果不依赖已有订单池文件，最早出现时间始终从原始日志重新计算。

## 数据来源

订单列表位于每条原始记录的：

```text
response.result.newOrderinfoMains.resultList
```

不处理订单类型、状态或业务字段；所有订单对象均按京东原始 JSON 保存。

## 命令与自动刷新

新增独立命令：

```text
python -m jd_monitor pool
```

默认读取 `data/raw_order_responses.jsonl`，写入 `data/order_pool.json`。命令支持显式指定输入和输出路径。

每次 `python -m jd_monitor capture` 成功完成所有分页采集后，自动从完整原始日志重建默认订单池。若用户为采集指定自定义原始输出路径，则订单池默认写到该文件同目录下的 `order_pool.json`。

## 写入安全

订单池先写入同目录临时文件，完整写入并刷新后再原子替换目标文件，避免中途失败留下半个 JSON。

以下任一情况视为构建失败：

- 原始日志某行不是有效 JSON；
- 原始记录缺少有效的 `captured_at`；
- `resultList` 存在非对象元素；
- 订单缺少非空 `orderId`；
- 订单池文件无法写入。

构建失败时不覆盖已有订单池。采集的原始响应已经成功落盘时，即使订单池刷新失败，也保留原始日志，并让命令返回失败提示。

## 输出与隐私

命令行只输出原始记录数、唯一订单数和订单池路径，不打印订单号、订单内容或 Cookie。

`data/` 继续由 Git 忽略。订单池包含客户及订单完整原始信息，只能保存在本机，不得提交或发送到聊天。

## 测试

自动化测试使用脱敏数据覆盖：

- 多条原始记录汇总为按订单号索引的订单池；
- 同一订单的最新完整对象覆盖旧对象；
- `first_seen_at` 保持第一次采集时间；
- 数字订单号转为字符串键；
- 损坏日志、缺少时间、异常 `resultList` 和缺少订单号时拒绝覆盖；
- 临时文件原子替换；
- 独立构建命令；
- 采集成功后自动刷新订单池；
- 命令输出不包含订单内容或 Cookie。

## 验收标准

1. 现有原始日志中的全部有效唯一订单进入订单池。
2. 每个条目包含最早 `first_seen_at` 和最新完整 `order`。
3. 重复执行构建得到一致结果。
4. 新采集完成后订单池自动更新。
5. 构建失败不会损坏已有订单池或原始日志。
