# 京东到家订单监控设计

## 目标

建立独立的本地 Web 项目，用于监控京东到家商家订单。用户可在浏览器中管理登录 Cookie、监控状态、轮询频率和推送配置；系统在命中目标订单时通过企业微信机器人、企业微信应用中转或邮件发送通知。

## 范围

包含：

- 京东到家订单 API 查询与状态映射。
- 通过可见浏览器人工验证并自动保存 Cookie。
- API 失效时回退到浏览器抓取订单。
- 本地网页管理界面、定时执行、运行记录和订单历史。
- 企业微信机器人、企业微信应用中转和 SMTP 邮件推送。

不包含：Electron 桌面壳、其他平台模块、用户账号密码自动登录、云端多租户、移动端适配。

## 运行边界

服务必须运行在用户可操作图形浏览器的本机。点击“登录/刷新 Cookie”后，后端启动非无头 Chromium 浏览器并等待用户完成京东到家验证；验证成功后保存浏览器上下文 Cookie。部署在没有图形界面的服务器上时，该登录方式不可用，界面必须显示明确提示。

## 架构

项目采用单进程本地服务：FastAPI 提供 JSON API、静态网页与后台任务；APScheduler 负责轮询；Playwright 负责登录和 API 失败后的网页回退；requests 负责优先调用订单接口。

```
浏览器管理页
      │ HTTP / SSE
FastAPI ── 配置与历史（本地 YAML/JSON）
      │
APScheduler ── 订单服务
                  ├─ requests：京东到家订单 API（优先）
                  └─ Playwright：人工登录、网页抓取回退
      │
通知服务 ── 企业微信机器人 / 企业微信应用中转 / SMTP
```

各组件只通过明确的数据对象交互：订单客户端返回标准订单列表，监控服务返回一次执行结果，通知服务只消费已构建的通知消息，Web API 只调用服务层而不直接操作浏览器或请求京东接口。

## 文件与数据

- `config/settings.yaml`：监控状态、调度频率、推送配置与全局通知级别。敏感的 SMTP 密码和应用中转密钥优先读取环境变量；界面保存的内容不写入日志。
- `data/cookies.json`：Playwright 格式的 Cookie，仅保存在本机并加入 `.gitignore`。
- `data/latest_orders.json`：最近一次执行的标准化订单和摘要。
- `data/orders_history.json`：按订单号、状态、日期去重的历史记录。
- `data/runs.json`：最近的运行时间、数据来源、成功状态和错误信息。

## 网页管理界面

界面为一个轻量单页应用，包含：

1. 概览：任务启停、立即执行、最近一次结果、订单数量、数据来源和最近错误。
2. 监控设置：可编辑状态码名称和“监控”开关；可编辑轮询分钟数；页面保存后立即重设调度器。
3. Cookie 登录：显示 Cookie 有效性、最近更新时间，提供“登录/刷新 Cookie”按钮及浏览器验证进度。
4. 推送设置：启用开关、渠道多选、每种渠道的目标地址、企业微信应用同步推送开关、测试推送按钮。
5. 记录：最近执行记录和历史目标订单。

## 订单与通知行为

订单客户端先校验并调用京东到家订单 API，查询当日订单并将订单统一转换为：订单号、状态、金额、实付、下单时间、配送时间、门店、门店编号和商品。API 不可用或 Cookie 失效时，使用 Playwright 打开订单页尝试抓取；两种方式都失败才标记本次运行失败。

启用了“监控”的状态为目标状态。每次轮询均推送所有命中目标状态的订单，保持参考项目的当前语义，避免持续待处理订单被遗漏。没有目标订单时不发送成功通知；执行失败时仍根据全局通知级别和模块通知开关发送失败提醒。

通知标题和正文采用参考项目的 Markdown 风格，展示日期、目标订单数、状态、订单号与门店，默认最多列出五条。渠道实现与京东业务解耦，并为每种渠道提供独立目标地址校验和测试发送。

## 异常处理

- Cookie 失效：记录失败原因，前端显示“需要刷新 Cookie”，并在已配置通知时发送失败提醒。
- API 请求、浏览器抓取或通知单渠道失败：记录具体错误；通知渠道互不阻断。
- 配置无效：保存 API 返回字段级错误，保留上一次有效配置和调度器。
- 重复点击登录：拒绝第二次请求，直到现有浏览器会话结束或超时。
- 服务重启：从配置恢复调度，使用已保存 Cookie；不会自动打开登录浏览器。

## 测试策略

- 单元测试：状态映射、订单标准化、目标订单筛选、通知标题正文、配置校验和调度频率转换。
- 服务测试：设置保存后重新调度、运行结果持久化、通知测试接口和 Cookie 登录互斥。
- HTTP 客户端与推送通道使用可控的模拟响应；不在自动化测试中访问京东或真实推送地址。
- 手工验收：本机点击刷新 Cookie 完成登录、立即执行、修改监控状态、发送测试推送和验证定时执行。

## 验收标准

1. 在本机浏览器打开管理页即可完成所有设置，不需要 Electron。
2. 用户完成可见浏览器验证后，Cookie 会持久保存且后续运行优先使用订单 API。
3. 可配置轮询、监控状态与三类推送渠道；保存后无需重启服务即可生效。
4. 每次目标订单查询结果会显示和持久化，命中状态的订单会按配置推送。
5. 项目不导入或运行 `auto-huawei` 的任何代码。
